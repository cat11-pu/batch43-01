# GSB Bugfix Task
## 题面
边界防火墙换成新解析器后，红队用一个自己拼的 IPv6 包就绕过了访问控制，报文带着路由头直接进了内网。这套设备还跑着老版本协议栈，升级要停机，安全队要求先在现有进程里把规则补上；被丢的包没有计数，事后根本说不清挡了多少。解析器对扩展头几乎没有约束：逐跳选项头出现在路由头之后仍然被接受；路由头类型零没被拒绝；分片偏移重叠的分片能重组成功；原子分片被当成非分片直接放行；超长负载选项声明的大小超过实际报文也不报错；扩展头链超过上限时解析器原地打转；目的选项里的未知动作位被忽略；认证头或封装安全载荷后面的上层头按错偏移解析；邻居发现错误消息引用的内层包没有校验；同一报文里出现两个分片头也照单全收；流标签和扩展头组合触发越界读；分片重组队列没有按源和标识隔离，两个设备的片混到一起。边界设备一停就是全城断网，没人敢拍板重启，新老协议版本还要同时支持。重叠分片必须丢弃并报 IPV6_FRAG_OVERLAP，不能进入重组队列；路由头类型零必须回参数问题消息且不得转发；扩展头超过八层必须抛 IPV6_EXT_CHAIN_TOO_LONG；错误消息只有命中活动流的内层五元组才能接受，否则丢弃并记 ICMPV6_ORPHAN。眼下回归集跑下来，失败项把报告刷满了。

## 运行方式
```bash
python -m pytest tests -q
```
