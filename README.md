# GSB Bugfix Task
## 题面
直播换到多码率自适应以后，观众反馈一到晚上就糊成马赛克。码率估算只看最后一个分片，网络一抖就切到最低档，之后再也升不回去；切换发生在分片中间，解码器直接报错，画面黑一下；视频切了档，音频还在旧码流上，十秒后口型完全对不上；不同码率的关键帧没对齐，切过去要等下一个关键帧，卡住两三秒；不连续序列号没有递增，时间戳突然跳回，播放器把后面的片段全丢了；拖动进度条时正好触发切档，落到了错误的码率分片；缓冲区占用只算视频，音频其实已经欠载；直播和点播两套控制器同时在跑，一个想升一个想降，来回横跳；清单里某个码率被下架，播放器还去请求，连续 404；切到需要新初始化段的编码，初始化段没重发，解码花屏；已经切到最低档，网络恢复后控制器仍然保守，整场都不升；切档后统计的卡顿次数没有归零，决策被历史数据拖住。abr_variant_ladder.py 的 AbrVariantLadder 要把码率切换限制在分片边界：只有关键帧对齐且不连续序列号一致时才允许切；音视频作为一组同时切换，共用一条时间轴；切换前预取目标分片的初始化段；缓冲区按音视频分别统计并取较小值决策；估算用滑动窗口而不是单个分片；清单变化时剔除失效码率并重新选档；直播和点播使用独立的控制器实例。两条硬门禁：任何一次切档后音视频时间轴必须连续，切档失败要回退到上一个可用码率而不是黑屏。这批十五条用例现在没有一条通过。

## 运行方式
```bash
python -m pytest tests -q
```
