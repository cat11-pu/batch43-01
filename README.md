# GSB Bugfix Task
## 题面
机房做外设管控，上了 USB 端口授权以后，安全巡检发现好几台机器上插着没登记过的网卡和存储，策略却显示已放行。现场看下来毛病不少：规则按端口路径写，同型号设备换到另一个口就被拒，换个机箱又莫名其妙能进；策略重载正好落在设备枚举中间，设备先被放行、驱动也绑上了，随后才收到撤销，已经晚了；复合设备只匹配到第一个接口，后面的网卡和存储接口全部漏判；白名单认序列号，序列号是设备自己报的，拿开发板写一个一样的就能过；拔插和授权同时发生，端口对象已经释放又被授权，进程直接崩掉；授权发生在读描述符之前，描述符里的设备类别和规则对不上也照放；被拒绝的设备还挂在总线上，内核模块照样加载；休眠唤醒以后授权状态没了，所有设备按允许处理；规则文件写错一个字段，加载失败后整体退化成全放行；两个口同时插设备，事件乱序，授权记录记到了另一个端口上；审计只写设备名不写端口路径，事后根本查不到是哪台机器。这批机器在产线上跑测试，停线一小时就是一笔钱，安全组要求所有判定都能回放到具体端口。没命中允许规则的设备必须在读描述符之前拒绝，不能绑定任何驱动；复合设备要逐个接口判定，有一个接口不允许就整台拒绝；规则加载失败必须继续用上一份有效策略，绝不能退化成全放行；端口对象释放后不得再被授权，重复事件必须幂等。

## 运行方式
```bash
python -m pytest tests -q
```
