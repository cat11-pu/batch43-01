# GSB Bugfix Task
## 题面
时间同步是审计重点，机房新上的网络安全时间客户端最近频繁回落到普通时间协议，安全队查下来发现它连服务器证书都没认真验。现场设备有的是新装的，有的是三年前的老固件，客户端一升级就有一批机器时间跳变；审计还要求能导出每台设备最近一次成功认证的服务器和算法。密钥建立阶段不校验预期主机名；凭据跨服务器复用，没绑定服务器标识；协商出的加密算法不在允许列表也接受；凭据过期不检查；同一随机数的响应被重放仍然调整时钟；唯一标识符不比对；协商失败时静默降级到旧版本；凭据用完后直接发无认证请求；密钥建立和时间同步并发，状态互相踩；服务端换主密钥后客户端凭据全废，形成重试风暴；响应里的原始时间戳不校验；时钟源切换时旧凭据和新服务器混用。机房有几百台设备，不能一台台手工换配置，客户端必须自己把失败模式收住，审计那边已经下了整改单，要求所有时间源可追溯。证书不匹配必须以 NTS_KE_TLS_INVALID 失败，失败后不得发出任何未认证的时间请求；随机数重放必须拒绝且不能调整时钟；凭据要持久化，重启后仍可用，凭据为空时只能停止轮询不能降级；算法不在允许列表必须报 NTS_AEAD_UNSUPPORTED 并中止。整改只给两周，不能靠逐台刷配置。

## 运行方式
```bash
python -m pytest tests -q
```
