# GSB Bugfix Task
## 题面
演唱会直播那晚，峰值观众八十万，卡顿率直接爆表，直播打包换成低延迟 HLS 以后，播放器端一直转圈，观众在弹幕里刷退钱。播放列表滚动时媒体序号跳变，播到一半卡死；分片时长忽长忽短，阻塞刷新等不到新内容直接超时；广告插入没有标 discontinuity，回来以后音画错位；播放列表窗口偶尔回退，已经播过的分片又出现；最后一片还没写完就写进列表，播放器请求 404；多码率流的序号不一致，切码率黑屏；服务器时间回拨，分片时间戳倒退；断流重连生成新的媒体序列，客户端当成换台；分片序号到上限回绕，老客户端解析失败；打包进程重启以后重复上传同一分片，CDN 上两份；低延迟模式下 part 目标时长和实际对不上；CDN 缓存旧播放列表，观众延迟越来越大。live_playlist_window.py 的 LivePlaylistWindow 负责 append、publish、rotate、recover。播放列表一旦发布，已经出现过的分片序号和时长不能再改；同一分片重复上传要按内容哈希幂等，不能产生两个 URI；媒体序列在打包进程重启后从持久化水位继续，不能回退；part 边界必须落在分片内，阻塞刷新在目标时长内返回，超时返回 504 而不是空列表。test_live_playlist_window.py 的十五项检查，长稳那条跑了六小时也没过，短测同样挂。

## 运行方式
```bash
python -m pytest tests -q
```
