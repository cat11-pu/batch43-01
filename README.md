# GSB Bugfix Task
## 题面
容器运行时换了新的系统调用过滤器编译器，红队用一个 32 位兼容调用就绕过了允许列表，直接读到了宿主机的文件。兼容模式的调用号与 64 位重叠，过滤器只按低位匹配；带高位标志的参数被截断后当成合法值；多线程安装过滤器时只作用到调用线程，其他线程还在裸奔；未知系统调用返回权限错误而不是未实现，程序的降级分支全走了错路；多个配置文件合并时后加载的整段覆盖前面的；跟踪动作没有挂跟踪器，进程直接挂起；体系结构检查缺失，跨架构调用照样过；过滤器长度超限被静默截断；没有设置禁止提权标志；安装过程中新起的线程逃过过滤器；配置热加载只影响新进程；过滤器里的参数指针没有解引用校验。运行时每天要起几万个容器，任何一次误杀都会被业务追着问，平台组已经把过滤器配置锁进代码仓库。沙箱逃逸的 PoC 已经发到安全群了，别再拖。未知系统调用必须回 ENOSYS，不能回 EPERM；多线程安装必须全部生效，失败时回 SECCOMP_TSYNC_FAILED 且不能留下半套过滤器；带 32 位兼容标志的调用必须拒绝并记 SECCOMP_X32_DENIED；过滤器超过四千零九十六条指令必须报 SECCOMP_FILTER_TOO_LONG。平台组要求今天就出一个能上线的版本。

## 运行方式
```bash
python -m pytest tests -q
```
