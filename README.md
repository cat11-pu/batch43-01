# GSB Bugfix Task
## 题面
递归解析集群上线新版本后，几个大客户的域名解析时好时坏，抓包发现别名链被跟到了完全不相干的区域，个别查询还在原地打转。权威侧说记录没改过，递归侧说缓存是对的，两边各拿一份日志，谁也说服不了谁；大客户已经发来正式函件，要求两天内给根因。解析器不检测别名成环，查询一直转到超时；链深超过上限时返回成功响应里的半截答案；越权目标的别名仍用原区域的信任去解析；别名和同名的其他记录同时存在也接受；链上生存时间没有取最小值，缓存时间被拉得很长；委托合成后的名字长度不检查；别名目标类别不一致还继续往下走；同名并发查询每个都去打上游，形成风暴；目标解析失败时把负缓存挂到原名字上；响应超过数据报大小却不置截断位；大小写不同的别名目标被当成两个名字；缓存里的链和权威侧变更后没有失效，旧目标一直生效。客户已经威胁要切走，值班发现同一个域名在两组解析器上返回的结果还不一样，排障时根本对不上。发现别名环必须返回服务器失败并带扩展错误码 CNAME_LOOP，不能返回半截答案；链深超过十六层必须返回服务器失败和 CNAME_CHAIN_TOO_LONG；越权目标不得写入缓存，也不能借用原区域的信任；同一名字的并发查询只能向上游发一次，所有等待者拿到同一结果。现在这套解析器的回归测试是全红的，没人敢上线。

## 运行方式
```bash
python -m pytest tests -q
```
