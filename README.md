# GSB Bugfix Task
## 题面
大世界流式加载一开，贴图花屏的反馈就没断过，环形上传缓冲最近把贴图搞花了，新场景里地面像打了马赛克。回绕以后覆盖了还在读的数据，地面贴图一块一块花；分配按四字节对齐，常量区要二百五十六字节，偏移整个错；一个大块上传把小请求全挤住，帧内干等十几毫秒；多线程分配没加锁，两个请求拿到同一段，模型顶点串了；上传完成标记记错帧，资源还没写完就被采样；部分更新只传了子区域，其余还是旧数据，版本号却加了；显卡掉线以后环形缓冲没重建，场景全黑；上传批次积压，帧时间忽长忽短；纹理 mip 上传顺序错，低 mip 把高 mip 覆盖了；环形缓冲耗尽就静默丢弃，模型缺贴图也没日志；回绕时没插屏障，GPU 读到半写的数据；统计里的可用字节算错，明明满了还显示有余量。staging_ring_alloc.py 的 StagingRingAlloc 负责 alloc、write、flush、recycle。同一段内存必须等引用它的完成标记就绪后才能复用，否则抛 RingExhausted，不能覆盖；偏移要满足资源类型的最小对齐，不满足抛 MisalignedUpload；耗尽时要阻塞到有可用段或者明确失败，不能静默丢数据；显卡恢复以后按新代次重建，旧代次的完成标记不能解锁新缓冲。test_staging_ring_alloc.py 的十五个用例，拿上一版回放数据跑，还是一条不过。

## 运行方式

```bash
python -m pytest tests -q
```
