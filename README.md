# GSB Bugfix Task
## 题面
固定团改成报名制以后，团长每周都要手工核对名单。候补第一个人被提上来，系统没发通知，等发现时位置已经过期；两个官员同时把不同候补拉进最后一个空位，两个人都进了团，实际人数超了一个；报名截止后还能提交，开打前十分钟又冒出来三个人；职责按报名时选的标签算，一个治疗切了输出照样占治疗位，真正的治疗被挡在外面；同一个人用两个角色各报一次，两个都算有效；有人被安排到候补，没进本却吃了逃兵惩罚；锁定时间按团长本地时区算，跨时区的团提前一小时锁死；玩家退队后名单里还留着，重新邀请提示已在团里；候补玩家没进本，首领击杀却记了他们的进度；上周的名单一键复制，把已经转服的人一起带了过来；团队取消后报名记录没清，下周新建的团继承了旧名单；团长在开怪瞬间踢人，名单和副本里的实际人数对不上。raid_signup_waitlist.py 的 RaidSignupWaitlist 要把报名、候补、入团、离团做成一条状态链：每个团本周期只有一份名册，名额按职责分组原子占用；候补顺序按报名时间和固定次级键排，提升时先占位再通知；同一账号在同一周期只能有一条有效报名；锁定时刻按服务器时间计算并落盘；取消团队要级联清空报名但保留审计；名单变更要同步到副本实例，开怪后只允许移出不允许补入；转服和删号的角色在复制名单时过滤掉。两条硬门禁：任何时刻入团人数不能超过配置名额，同一个角色不能同时出现在主力和候补两份名单里。tests/test_raid_signup_waitlist.py 的十五条断言目前全挂。

## 运行方式
```bash
python -m pytest tests -q
```
