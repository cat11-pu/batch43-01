# GSB Bugfix Task
## 题面
跨地域专线最近频繁出现大包不通，运维在两边抓包，发现叠加网络网关对路径最大传输单元的处理完全失控，一会儿把值压到五百多，一会儿又完全不发控制消息。监控上只看到重传率升高，没人把它和路径值被压低联系起来。网关会采信伪造的需要分片消息，把某条路由的路径值永久压低；缓存只按目的地址存，不同隧道共用一份；最大报文段钳制只改握手第一个包，不改回应包；带禁止分片标志的包超过上限被丢弃却不回控制消息；控制消息引用不足八字节也拿来更新缓存；缓存老化时间过长，路由变更后仍用旧值；不同封装开销的隧道共享缓存；内层禁止分片置位时外层仍然做分片；IPv6 数据包过大消息的类型和代码没校验；并发更新同一目的缓存，后写覆盖先写；黑洞检测把应用层超时也算成路径问题，缓存值越压越低。这套网关同时承载办公和视频，不能靠重启恢复，值班还发现同一条专线在两个机房看到的路径值差了两百多，故障定位一直被带偏。控制消息必须和内层五元组及最近发出的报文对上，否则丢弃并报 PMTU_ICMP_UNVERIFIED；IPv6 路径值低于 1280 时只能钳到 1280，不能继续下压；路由切换后缓存必须原子失效，不能有报文继续使用旧值；重启后缓存可以重建，但超过存活时间的旧低值不得复用。专线还断着，先把这条止血。

## 运行方式
```bash
python -m pytest tests -q
```
