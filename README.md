# GSB Bugfix Task
## 题面
移动办公终端换成自研的 WireGuard 接入网关后，地铁里切基站就断线，运维看握手日志发现同一个公钥一分钟内建了十几套会话。网关收到 Cookie 回复不校验来源，谁都能拿它触发握手；同一份握手初始化包重放，网关每次都新建会话，序号从零开始；对端换地址后网关只看源地址就更新漫游端点，没有用已认证的传输包确认；进程重启后每对端的重放计数器清零，旧包又能过；保活包还发往旧端点，新地址一直收不到；允许地址列表重叠时后加载的覆盖前面的，流量走了错误的对端；预共享密钥对不上握手也能完成；会话索引冲突时后到的直接覆盖前一个；两个握手线程并发处理同一公钥，各自建一套状态；传输数据在握手未完成前就被接收；对端删除后保活定时器还在跑；系统时间跳变后重钥永远不触发。运维试过让客户端重连，重连十次还是断，计费会话也跟着乱。客服已经压不住了，先把漫游状态收住。同一公钥的握手重放只能命中已有会话，不能重置重放计数；Cookie 校验失败必须丢弃并记 WG_COOKIE_INVALID，不能继续握手；漫游端点只能由已认证的传输包更新，否则保持原端点；重启后要恢复每对端重放计数器，低于已见序号的包按 WG_REPLAY 丢弃。运维要求切换过程不能断超过三秒。

## 运行方式
```bash
python -m pytest tests -q
```
