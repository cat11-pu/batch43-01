# GSB Bugfix Task
## 题面
数据库侧把认证升级到带通道绑定的口令认证，数据库管理员发现走加密链路的连接还是能被中间人降级，而且不同实例对通道绑定的算法不一致。数据库驱动版本不统一，有的客户端只支持旧机制，运维不敢一刀切禁掉；安全基线扫描把不带通道绑定的远程认证直接判高危。实现里计算服务端端点绑定值时取错证书，用了链上的中间证书；客户端随机串没检查是否是组合随机串的前缀；迭代次数低于下限也接受；空盐值也能算；服务端最终签名不验证；用户名没做国际化归一；授权身份指向别的用户也放行；客户端最终消息可以跨连接重放；带绑定能力不可用时静默降级到不带绑定；存储密钥的派生版本不一致；同一用户并发认证时随机串复用；认证成功后连接对象没有标记，后续命令仍走匿名权限。数据库有两百多个实例，版本参差，不能强制统一升级客户端，安全基线还要求所有远程认证必须能证明通道绑定生效。通道绑定不匹配必须报 SCRAM_CHANNEL_BINDING_MISMATCH 且不能回退到不带绑定；客户端随机串不是组合随机串前缀时必须报 SCRAM_NONCE_INVALID；迭代次数低于四千零九十六必须报 SCRAM_ITERATIONS_TOO_LOW；服务端最终签名验证失败时不得把连接标记为已认证。值班发现同一套账号在应用服务器上能过，在跳板机上却一直失败，排查很慢。

## 运行方式

```bash
python -m pytest tests -q
```
