# GSB Bugfix Task
## 题面
省网边界路由器上线 RPKI 源验证后，一次上游配置变更把几条无效路由又放了进来，流量绕了一大圈才恢复。值班发现验证结果只在本地进程里，邻居压根没收到；无效路由因为本地优先级高，压过了有效路由；来源 AS 集合被当成任意一个匹配就放行；最大前缀长度字段没看，超长明细照样通过；缓存里的授权对象过期后没有刷新，旧结果一直生效；路径泄露检测只看到第一跳，AS 路径中间的环路没识别；路由刷新时验证状态被清零，半张表变成未知；多条授权对象冲突时取第一条，后来更新的被忽略；IPv6 的授权对象被套到 IPv4 前缀上；撤销路由时没有清掉无效标记，同前缀重新宣告直接继承；两个更新线程同时改同一前缀，后写的覆盖先写；软重配后策略链丢了源验证环节。这套验证跑在边界路由器上，邻居有十几家，策略一乱就是大面积绕路；割接前两台路由器的验证结果必须一致，否则告警没有统一口径。上游已经发来路由泄露告警，今晚必须让策略生效。无效路由不得装表，必须打上 BGP_ROV_INVALID 并拒绝向邻居宣告；前缀长度超过授权上限一律判无效；授权对象刷新必须整表原子替换，刷新期间不能出现半套结果；同一前缀撤销后重新宣告，旧验证状态必须先清空再重算。割接窗口只到凌晨两点。

## 运行方式
```bash
python -m pytest tests -q
```
