# GSB Bugfix Task
## 题面
我们给园区做的 MQTT 接入最近被安全部点名，整改通知已经发到邮箱。普通设备订阅井号通配符，能收到别的租户的主题，等于把所有传感器数据都看了一遍；美元符号开头的系统主题没拦，谁都能读 broker 的连接数和流量指标，连管理员密码错了几次都看得到；ACL 改完不生效，运维只能重启 broker，一重启全园区掉线，门禁和空调一起停摆；QoS2 的发布报文重传时，同一条消息投递了两次，电表读数直接翻倍，月底账单对不上；保留消息不按主题权限过滤，新订阅者一上来就收到上个月的旧指令，水泵被远程开了一次；同一个 clientId 两头登录，旧连接没被踢掉，消息随机分给两边，指令时灵时不灵；遗嘱消息在客户端正常断开时也发了，告警群里天天误报，值班同事已经不看群；inflight 窗口满了以后新消息直接丢，不排队也不报错，采集中间断了一大段；桥接配成双向，两个 broker 之间的消息来回循环，CPU 打满，网关热得烫手；载荷超过限制被截断后还继续转发，下游解析出一堆半截 JSON；TLS 客户端证书的 CN 和用户名不一致也放行，拿别的设备证书能顶替上线；共享订阅组的成员掉线以后还占着轮询名额，活着的节点反而分不到消息。mqtt_topic_matrix.py 的 MqttTopicMatrix 要负责主题鉴权、会话和投递。订阅鉴权按主题层级逐级匹配，通配符不能越出租户前缀；QoS2 按报文编号去重，重复投递不得重复入库；同一 clientId 只允许一个活动会话，接管前必须先断开旧连接；超限或畸形载荷直接断开并写审计，不许截断转发。安全部只给两周整改，先把越权订阅这条堵死。

```bash
python -m pytest tests -q
```
