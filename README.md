# GSB Bugfix Task
## 题面
多线程改造本来是为了稳住帧率，结果先稳住了崩溃率，多线程渲染改造完，崩溃和黑块一起冒出来，挂机测试一晚上能掉十几回驱动。录制命令的时候资源被提前释放，画面随机黑一块；帧边界 fence 等错对象，CPU 提前复用常量缓冲，模型位置乱飞；窗口 resize 以后命令缓冲还引用旧尺寸的附件，画面撕裂；设备丢失恢复时旧命令队列没清空，直接崩；同一个资源被两个线程同时写屏障，验证层一直报错；提交顺序和录制顺序不一致，透明物体排序全乱；一帧里命令缓冲数量暴涨，内存不释放；关掉垂直同步以后 fence 一直等不到，帧卡死；后台加载线程和渲染线程共用上传队列，互相阻塞；退出游戏时还有未完成命令，驱动报错；多 GPU 节点各自提交，跨节点资源没同步，贴图错位；录制失败以后命令缓冲泄漏，挂机一晚内存涨了几个 G。frame_command_fence.py 的 FrameCommandFence 管 begin、submit、wait、recycle。每帧资源必须在引用的 fence 完成后才能复用，提前复用要抛 ResourceInUseError；resize 和设备丢失恢复要等待并重建全部在途帧，旧代次提交直接丢弃；提交顺序必须和录制序号一致，乱序提交返回 out_of_order；退出时要在超时内完成或取消所有在途命令，不能泄漏。test_frame_command_fence.py 的十五项检查，设备丢失那条必崩，剩下的也没撑住。

## 运行方式
```bash
python -m pytest tests -q
```
