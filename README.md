# GSB Bugfix Task
## 题面
公会科技树开放捐献以后，几个大公会的科技进度全乱了。捐献超过当前等级所需点数，多出来的部分照扣不误，等于白捐；两个官员同时点不同的科技，两条研究同时跑起来，共用同一个研究位；研究完成时公会正好解散，点数扣了，增益谁也没拿到；完成时间按本地时钟算，夏令时那天提前一小时结束；中途取消研究，返还了全部材料，实际应该按进度折算；网络重试让同一笔捐献记了两次，科技直接跳级；数据表更新后，三阶科技没点前置也能开始研究；捐献和完成同时发生，最后一级被算了两遍；公会等级掉下去以后，正在研究的科技继续跑，完成后无法生效；服务器重启，研究进度从零开始，材料已经扣完；已经完成的科技还能再捐，点数进了黑洞；研究位空闲时，界面显示还在研究中，怎么点都没反应。guild_research_lab.py 的 GuildResearchLab 要维护公会的研究位和科技等级：同一公会同一时间只能有一个进行中的研究；捐献用条件更新，超过剩余需求的点数原样退回；开始研究校验前置、公会等级和材料，全部满足才扣；完成和研究位释放是一个原子转换，只发一次增益；取消按已完成比例返还，返还额有上限；进程恢复时用结束时刻和剩余进度重建研究位；科技等级只增不减，重复完成直接拒绝。两条死线：捐献总额不能超过该级所需点数，同一笔捐献即使重复提交也只入账一次。guild_research_lab 的十五项检查铺开，现在没有一项能过。

## 运行方式
```bash
python -m pytest tests -q
```
