# GSB Bugfix Task
## 题面
团队副本改成需求优先掷骰以后，分配争议比之前还多。掉线的人在读条结束前被判定为放弃，结果回来发现自己赢了，装备却已经寄给了别人；两个人掷出同样的点数，系统把同一件装备发了两份；团长在暂停状态下打开分配，倒计时还在走，最后没人拿到；团长手动分配给一个已经退队的玩家，装备直接消失，尸体上也没有；需求按钮对不能装备的职业也亮着，贪婪在需求之前就被允许；同一具尸体被重新打开，上一轮的骰子记录又出现一次；自由拾取模式下有人先捡走了，掷骰结果后到，系统又发了一件；玩家重连后掷骰加成被重复计算，点数高得离谱；分配规则从需求优先改成队长分配，进行中的那一轮结果按新规则重算；跨服同名玩家的掷骰记录混在一起，A 的点数记到了 B 头上；赢家背包满了，装备卡在待领取里，没有邮件兜底；点数相同时每次查询随机选一个赢家，两个界面显示不同的获胜者。loot_roll_tally.py 的 LootRollTally 要把每个掉落槽位的掷骰做成独立状态机：开始、投票、截止、结算、交付，截止和结算在同一把锁里完成；掷骰记录按角色编号而不是名字索引；点数相同用固定的次级键决胜并写进结果；超时、退队、掉线统一按放弃处理；同一掉落槽位只允许一轮有效掷骰；赢家背包不足时转邮件并标记来源；规则变更只影响下一轮，不改写已结算记录；重启后未结算的掷骰要能恢复截止时间或直接按已有票数结算。两条不能破的线：一件掉落只能交付一次，结算结果一旦写入就不能被后来的重连或改规则翻掉。tests/test_loot_roll_tally.py 里那十五项，今早跑到现在没有一项是绿的。

## 运行方式
```bash
python -m pytest tests -q
```
