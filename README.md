# GSB Bugfix Task
## 题面
构建集群的沙箱最近被安全研究员绕过了，入口是内核异步接口，明明禁了打开文件调用，换个操作码照样能打开宿主文件。平台组做过一次压测，环一多，固定文件表的释放顺序就开始乱，最后只能整机重启；审计要求每次拒绝都能看到是哪个构建任务、哪个操作码。检查器让打开文件的操作码没进允许列表却执行成功；注册缓冲区绕过用户地址校验；注册身份能换凭据；带异步提交标志的请求逃到不受限的工作线程；完成队列溢出后完成事件被覆盖，构建进程等不到结果直接挂死；环的映射大小和提交队列不一致；链接请求中第二个失败时，前面的操作已经生效且无法回滚；内核轮询线程跑到控制组外面；固定文件表跳过路径检查；超时请求挂错目标；关闭环时在途请求没有取消；同一进程并发创建多个环，共享的固定文件表互相污染。沙箱每天要跑几万个第三方构建任务，不能靠人工巡检，恢复时也不能把宿主暴露出来。不在允许列表的操作码必须在提交时以 EPERM 失败，不能执行；链接请求必须整体原子，第二个被拒时第一个也不能留下可见结果；注册缓冲区索引越界必须报 EFAULT 且不能读内核内存；关闭环时必须取消在途请求并释放固定文件，重复关闭不能二次释放。安全研究员留下的话是，别只堵一个入口。

## 运行方式
```bash
python -m pytest tests -q
```
