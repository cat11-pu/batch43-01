# GSB Bugfix Task
## 题面
统一认证接入单点登出以后，客服收到的投诉都是同一个路子：在一个应用里点了退出，另外两个应用还停在登录态，账号被人接着用。排查下来问题一大堆：同一个会话的登出通知在重试队列里发了两遍，第二遍把用户刚重新建立的会话也踢了；登出令牌拿用户标识当会话标识用，一次退出把同一个人三台设备的会话全清了；第三方应用登记的回调地址只比对前缀，填个外部域名照样收到带用户标识的跳转；浏览器拦了第三方 cookie，前端通道的 iframe 根本没跑，后台的记录却是已送达；回调超时后重试没有次数上限，队列越堆越长，最后整条通道卡死；两个管理员同时执行强制下线，各自签出一枚令牌，客户端收到两份互相打架的结果；用户改完密码，旧会话标识没有作废，隔天还能拿旧令牌换新令牌；退出请求正好撞上令牌续期，续期成功以后会话又活了过来；发布重启把内存里待投递的通知全丢了，用户以为退出了其实没退；几台机器的时钟差了几分钟，令牌签发时间被判成未来，对端直接丢掉。这套服务挂在集团统一认证入口，白天不能停，接入方四十多个，谁都不愿意改代码。同一个会话标识只能签出一枚有效登出令牌，重复触发返回 already_logged_out，不能波及别的会话；投递失败必须进重试队列，三次之后标成 dead 并保留可查状态，不能无限重试；退出和续期撞上时必须让退出赢，续期请求返回 invalid_session；进程重启后未完成的投递要继续，不能漏踢也不能重复踢。

## 运行方式
```bash
python -m pytest tests -q
```
