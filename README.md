# GSB Bugfix Task
## 题面
文件解压服务上线后，安全响应中心用一个软链接就把压缩包里的文件写到了宿主机的配置目录，根因是路径解析没锁在根目录下。租户上传的压缩包里有几万个文件，解压到一半失败时留下的半成品比成功还难清理；客服要求能告诉租户是哪个文件越界，而不是只回一句解压失败。解析器允许指向根外的软链接；进程文件描述符的魔法链接也能绕过；检查完目录被改名，真正打开时已经跑出根；参数里带绝对路径会重置根；软链接后面跟上级目录分量继续向上；跨挂载点也放行；大小写不敏感文件系统上同名目录串用；根外文件的硬链接能创建；国际化归一化后路径长度变化，校验和打开用的不是同一个名字；空路径被当成根目录；并发解压互相覆盖临时文件；解压过程中目标目录被换成软链接，写完后才发现落点不对。这个服务给外部租户用，每天几万次上传，不能靠人工看日志，运维还发现磁盘满和路径越界在日志里长得一模一样。任何逃出根目录的路径必须抛 PathEscapeError，且不能留下已创建的文件；并发改名或替换软链接的竞态下，打开操作仍必须原子地锁在根内；绝对路径和上级目录分量必须报 PathNotBeneath；写到一半崩溃时临时文件要清理，目标路径只能看到旧文件或完整新文件。这个接口每天调用量很大，不能加全局锁。

## 运行方式
```bash
python -m pytest tests -q
```
