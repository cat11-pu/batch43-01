# GSB Bugfix Task
## 题面
机房边界时钟最近被安全审计点名：一台接入层设备伪造 PTP announce，把自己宣告成最高优先级主时钟，两个机房的两百多台基站跟着它跳时；攻击者还能重放旧的 announce，让从时钟在真主时钟和假主时钟之间来回切换；Sync 和 Follow_Up 的序号没有绑定，伪造的跟随报文能把时间戳改成任意值；透明时钟的修正字段可以被中间人重复累加，链路越长偏得越多；单播协商没验来源，任意地址都能请求单播会话；硬件时间戳队列溢出后静默丢包，攻击者用洪泛把队列打满；闰秒和步进没有审计，攻击者可以借跳变让证书校验失败；时钟等级变化没有重新宣告，假主时钟掉线后从时钟还抱着旧源；两个主时钟同时被选中，从时钟来回切；重启后把旧偏移写回硬件，第一次同步就是错的；配置模板和现网版本不一致，安全基线无法确认当前主时钟身份；审计只记录时间偏差，不记录主时钟身份和报文来源。ptp_spoof_guard.py 的 PtpSpoofGuard 要校验 announce 来源和优先级、绑定 Sync/Follow_Up 序号、限制修正字段累加、单播协商验来源、时间戳队列洪泛保护、步进审计和主时钟身份记录。硬门禁：伪造 announce 或来源不在白名单必须拒绝并记录；同一 Sync 序号只能配对一次，重复或错配返回 replay；修正字段累计超过阈值必须拒绝；步进或闰秒跳变必须写审计并触发告警。test_ptp_spoof_guard.py 的十五项检查现在全部失败，主时钟身份和报文重放两条链都没过。

## 运行方式
```bash
python -m pytest tests -q
```
