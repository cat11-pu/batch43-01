# GSB Bugfix Task
## 题面
授权服务器接入推送授权请求之后，客户端把授权请求先推到后端，最近被安全响应中心发现同一个请求地址能换出两个授权码。业务方接入时只拿到一份通用错误码文档，分不清是请求地址过期还是客户端配错；授权服务器一重启，十几个业务方同时重试，日志瞬间被刷满。存储允许请求地址发过码后再次使用；推送阶段的对象不验签也接受；推送阶段的客户端编号和授权阶段不一致仍继续；请求地址没绑定客户端，换个客户端也能用；过期时间不检查，隔天还能换码；回调地址只做前缀匹配；代码交换校验允许明文方式；同一请求地址并发授权各发一个码；参数重复时前一个生效；请求对象里的权限范围和推送外层不一致时直接取并集；消费记录只在内存，重启后全部复活；授权码已经发完但推送记录没有标记消费，重试又发一个。这套授权服务器承载十几个业务方，不能靠停机清理内存里的脏数据，业务方还要求推送失败时能明确知道是参数问题还是客户端问题。同一请求地址并发授权只能发出一个码，第二个必须返回 invalid_request_uri；过期或已消费的请求地址必须返回 invalid_request_uri 且不能发码；请求地址绑定客户端，换客户端要报 invalid_client；策略禁用明文校验方式时必须返回 invalid_request。安全响应中心要求所有推送记录可追溯，不能只留内存计数。

## 运行方式
```bash
python -m pytest tests -q
```
