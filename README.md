# GSB Bugfix Task
## 题面
特权辅助程序做权限收缩后，安全扫描发现它还能重新拿回刚丢掉的网络管理能力，等于白降权。边界能力集在切换用户后没有继续收窄；环境能力集在设置了设置用户标识的程序里还能存活；文件能力在禁止提权标志下仍然生效；程序用保留能力把自己的能力又加回边界集；执行新程序前有效能力集没有清空；保持能力标志没设，切换用户后能力全丢导致业务失败，运维只好又加回去；用户标识变化时允许能力集没有重算；可继承能力集把能力泄漏给子进程；能力版本与内核不一致时静默降级；并发创建子进程和执行程序之间状态互相踩；丢弃能力失败却没有报错；根目录被压缩权限后能力仍然保留。这个辅助程序挂在所有容器启动路径上，停一分钟就是一片发布失败；安全队要求降权后不能再拿回任何能力，运维试过直接去掉文件能力，业务又起不来；内核版本跨了两个大版本，行为有差异。提权链已经打通到宿主机了，先把这个辅助程序收住。切换用户执行新程序时必须清空有效和允许能力集，否则报 CAP_TRANSITION_DENIED；环境能力集不得跨设置用户标识的执行存活；边界能力一旦丢弃就不能再加回，再加回要回 EPERM；子进程不得继承可继承能力集之外的能力。安全队说这个洞已经进了外部通报，今晚必须堵上。

## 运行方式
```bash
python -m pytest tests -q
```
