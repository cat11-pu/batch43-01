# GSB Bugfix Task
## 题面
修理系统改版后，金币流水和耐久数据对不上。修理费按当前耐久算，恢复却按最大耐久写，越修越便宜；一键修理把另一套装备方案里的备用武器也修了，玩家根本没穿；耐久掉到零以后属性还在生效，必须重登才消失；两下修理请求同时进来，金币扣了两次，耐久只加一次；公会修理折扣在计算器里乘了一遍，结算时又乘一遍；交易过程中修理，修的是原主人的那一份，新主人拿到还是坏的；已经损坏的装备还能挂拍卖，买家拍下才发现不能用；死亡扣耐久的事件比修理晚到，刚修好的武器又掉一截；界面显示修理费几十铜，实际扣了几金；装备最大耐久被腐蚀降低后，修理把它恢复成最初的上限；战斗中也能修理，武器属性在攻击判定中途跳变；服务器在扣钱之后、写耐久之前重启，金币没了，装备还是坏的。durability_repair_bench.py 的 DurabilityRepairBench 要把修理做成一次带快照的结算：服务端按装备当前耐久、最大耐久和折扣配置算价，客户端展示的数字只作参考；扣金币和写耐久在同一个事务里；同一件装备的修理请求带物品修订号，过期请求直接拒绝；修理前重新校验归属、装备状态和战斗状态；折扣只应用一次并记录来源；最大耐久被永久降低时按降低后的值恢复；重启后未提交的修理要么完整生效要么完全回滚；每次修理写一条包含修理前后耐久的流水。两条硬线：金币扣除次数和耐久恢复次数必须一致，任何一件装备的耐久不能超过它当前的最大值。仓库里那十五条用例今天还是一条都没过。

