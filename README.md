# GSB Bugfix Task
## 题面
财务 VPN 的二次验证最近频繁提示验证码错误，安全审计还发现同一个码能被用两次。验证码用过之后计数器没有原子递增，并发请求两个都成功；窗口放宽到前后各三十步，暴力尝试空间变大；每个用户的时间漂移没有单独记录，服务器时间一抖就全错；密钥在不同用户之间复用；只支持 SHA-1，配置成 SHA-256 的用户永远对不上；计数器更新不是原子操作；备用码用过一次没有作废；系统时钟回拨后旧码又能用；二维码 provisioning 把密钥写进访问日志；限流只按地址不按账号，代理后面全被当一个人；服务重启后最后使用计数丢失；同一账号在两台设备上注册了同一个密钥。财务有六百多个账号，报税期每天登录十几次；安全审计把重复使用列为高危，运维不敢清缓存，怕影响正常用户；客服只能让用户等下一个周期，厂商说计数器是内存里的，重启会丢。整改通知已经下发。财务那边催得很急，先别把人锁在外面。同一个验证码只能成功一次，重复提交报 TOTP_REPLAY；计数器递增必须原子，并发校验只能有一个成功；漂移超过前后一步必须报 TOTP_WINDOW 并拒绝；重启后要恢复每个用户的最后计数和密钥版本。财务说今晚必须能报税，别再折腾他们。

## 运行方式

```bash
python -m pytest tests -q
```
