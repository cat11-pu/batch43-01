# GSB Bugfix Task
## 题面
统一登录的后台最近出现越权，一个普通账号在连接池里复用了服务账号的绑定，直接读到了目录管理区。池化连接先用服务账号绑定，再切用户时只改了用户名，授权身份没重置；策略禁止匿名绑定，空凭据却仍然返回成功；引用追踪跟到了白名单外的目录，把内部结构泄出去；分页结果的 cookie 在两次查询之间复用，数据串页；StartTLS 没有强制，明文绑定也接受；密码策略响应被忽略，账号锁定后池里的连接还能用；SASL 被降级成简单绑定；DN 归一化没处理大小写和空格，同名账号串用；同一条连接并发重绑，身份互相覆盖；连接归还池子时还保持着用户身份；根目录信息接口暴露了过多属性；目录服务一抖，所有后台都登不进去。目录里有几万个账号，连接池峰值上千；越权那条路径是安全演练时发现的，审计要求每次重绑都能追到原身份，运维不敢直接重启目录服务。业务方还在等着登录恢复。安全队要求先把服务账号的权限收掉。重绑必须原子重置授权身份，旧身份不能残留；匿名绑定必须拒绝并报 LDAP_ANONYMOUS_DENIED；引用目标不在白名单内必须报 LDAP_REFERRAL_BLOCKED；已锁定账号即使命中池化连接也必须绑定失败。后台登录一挂，值班电话就没停过。

## 运行方式
```bash
python -m pytest tests -q
```
