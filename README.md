# GSB Bugfix Task
## 题面
剧情对话一多，背景音乐就开始抽风。语音检测把呼吸声当成说话，音乐刚恢复又压下去，整段像在打拍子；释放时间设得太短，一句话说完音乐猛地弹回来，耳机里咚一声；同时有三个语音源在播，压音量按每个源各算一次，音乐几乎被压没；压音发生在总线限幅之后，语音一响反而更容易削顶；恢复时读的是当前音乐音量，不是压音前的值，几轮下来音乐越来越小；载入剧情快照时正好在压音，快照结束后音乐一直闷着；只压了干声没压混响发送，语音结束以后厅堂里还糊着一层音乐；参数按音频块更新，块边界能听到台阶；左右声道各自判断语音，压音量不一样，声像往一边偏；语音流异常结束没有释放事件，音乐整场都起不来；对白和过场两套规则同时命中，谁最后写入谁生效，结果不可预测；采样率从四十八切到四十四点一，攻击和释放时间跟着变短。dialogue_ducking_mixer.py 的 DialogueDuckingMixer 要把压音做成采样级包络：语音检测带迟滞和最短语音时长，静音帧不触发；多个语音源按最大值合并，不累加；压音作用在音乐总线进入主限幅之前，并同时作用于干声和发送；恢复目标取压音前的基线增益，不读当前值；攻击和释放时间按秒配置，随采样率换算成样本数；快照切换和跳转要重置包络并平滑过渡；每个声道共用一份判定。两条硬门禁：压音包络必须连续无台阶，任何一次语音结束后音乐增益要精确回到压音前的值。tests/test_dialogue_ducking_mixer.py 的十五项断言现在全部失败。

## 运行方式
```bash
python -m pytest tests -q
```
