# GSB Bugfix Task
## 题面
城域网扩容后，几条跨区专线时通时断，运维在设备上看到标签转发表里同一个标签指到了两个下一跳。分配器把保留标签零和三也分给了业务；LSP 拆除时标签没有回收，跑一周池子就见底；倒数第二跳弹出后 TTL 没有递减，traceroute 看不到真实路径；等价路径哈希按包做，同一流被拆到两条链路乱序；标签栈深度超过上限没有报错，直接截断后转发；同一个转发等价类被分配了两个标签；主备切换时备用路径还没装好就切过去，黑洞几百毫秒；进程重启后标签表从空开始，旧标签被重新分给别的 LSP；入标签映射和下一跳映射对不上，包被送到错误端口；保留标签十五也被接受；TTL 传播被全局关掉，跨域排障全靠猜；两个分配线程并发申请同一标签，双分配。这条城域网承载政企专线和基站回传，断一条就是一片投诉；运维翻了三天的配置，还没找到是哪个 LSP 泄漏。割接方案已经批了，今晚必须落地。割接窗口就剩四十分钟，回退脚本还没测。保留标签必须拒绝并报 MPLS_LABEL_RESERVED；同一转发等价类并发申请只能得到一个标签，第二个请求返回同一个值；重启后要重建标签表，仍在用的 LSP 标签不得被重新分配；弹出标签时必须递减 TTL 并保留实验位。运维要求切换期间丢包不超过三个。

## 运行方式
```bash
python -m pytest tests -q
```
