# GSB Bugfix Task
## 题面
多租户平台统一校验各家的身份令牌，上个月一家签发方轮换密钥，结果全平台一半请求报未授权，另一半又接受了已经下线的旧密钥。运维翻缓存发现同一个密钥编号在不同签发方下指向完全不同的公钥；客户要求给出每次验签用的是哪把密钥、什么时候拉取的。校验器遇到未知密钥编号每个请求都拉一次密钥集；缓存永不过期，吊销的密钥一直可信；缓存键只有密钥编号，不同签发方的同名编号串用；算法混淆，非对称公钥被当成对称密钥；密钥用途和算法不校验；密钥集地址允许明文协议和跨主机跳转；上游返回半份密钥集也整体覆盖好缓存；轮换重叠期新旧密钥只有一个能用；证书链不验证；并发刷新互相覆盖；令牌里的签发方和缓存来源不一致也通过；缓存刷新时读线程拿到空表，所有请求一起报未授权。平台上有几十家签发方，配置各不一样，不能要求他们同时改，客服已经收到多家客户投诉，说同一批令牌在十分钟内一会儿能过一会儿不能过。未知密钥编号在三十秒内对同一签发方只能触发一次刷新，风暴请求必须合并；密钥集删除的密钥在缓存过期后必须立即失效，轮换重叠期内新旧密钥都可验但只限同一签发方；算法不匹配必须报 JWKS_ALG_MISMATCH；缓存必须按签发方和密钥编号隔离，绝不能拿一家的密钥验另一家的令牌。轮换那天值班不敢重启服务，怕缓存一清空全量请求打崩签发方。

## 运行方式
```bash
python -m pytest tests -q
```
