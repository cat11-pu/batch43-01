# GSB Bugfix Task
## 题面
视频会议网关做完加密改造后，安全审计拿重放工具打媒体面，发现同一段语音包隔几秒再发，接收端照样解密播放，会议室里能听到重复的音节。更糟的是一次通话串进了上一通的声音，终端跟着重连。查下来十六位序号从 65535 回到 0 时回绕计数被清零，旧包重新落进窗口；窗口只记最高序号，乱序但没过期的包被误丢；换密钥后控制包的索引没跟着换，认证一直失败；密钥标识对不上仍然拿去解密；控制包自己的重放窗口没有维护；双向流的同步源标识冲突时，两条流的状态被合成一条；控制包重传的复合包被重复计入抖动；四字节截断的认证标签也接受；密钥包用到上限不强制重钥，一把密钥一直用；握手重传产生两套加密上下文，旧密钥还在解包；首个带标记的包之前到达的乱序包被当成新流；媒体线程和密钥线程同时改密钥世代，切换瞬间读到半新半旧的密钥。这套网关会议和固话共用，升级窗口只有凌晨两小时，不能靠停机清状态。同一流标识和索引的重放包必须丢弃并返回 SRTP_REPLAY，不能推进回绕计数；序号从 65535 回到 0 只认一次，之后重复的一律拒绝；换钥要原子生效，切换期间不能用错密钥解出明文，旧世代的包要拒绝；达到密钥包上限必须强制重钥并以 SRTP_KEY_EXPIRED 拒绝旧密钥。审计报告已经把重放列为高危，回归测试却还是一片红。

