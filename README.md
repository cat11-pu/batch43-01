# GSB Bugfix Task
## 题面
容器节点被一个递归创建进程的镜像打挂过一次，运维发现进程数限制根本没兜住，父控制组的配额被绕过。限制值差一，实际能创建的进程总比配置多一个；进程在两个控制组之间迁移时，两边同时计数，短时间超限；线程模式的控制组把进程数算到了错误的层级；嵌套控制组里的子组各自限额，父组没有汇总，加起来远超节点容量；事件计数没有清零，告警一直重复；僵尸进程回收前没有释放配额；并发迁移时两个请求都以为还有余量；根控制组的限制被忽略；服务重命名作用域后限制丢失；控制组命名空间隐藏了真实路径，运维看错层级；控制器先禁用再启用后状态没有恢复；节点重启后限制没有重新应用。这个节点跑着两百多个租户容器，一挂就是一片 502；平台组要求限制值配下去就必须生效，不能再靠重启节点兜底，上次恢复花了十分钟；安全队要求进程数限制和内存限制一样可靠，监控上却只有总数，没有按控制组拆分。运维现在不敢放开部署，先把这个限额做扎实。达到上限时创建进程必须回 EAGAIN，不能返回其他错误；迁移必须原子完成，不能出现两个控制组同时超限的中间态；僵尸进程在回收前必须继续占用配额；重启后要从统一层级恢复所有限制，不能回到无限制状态。平台组要求上线前先做一次压测。

## 运行方式
```bash
python -m pytest tests -q
```
