# GSB Bugfix Task
## 题面
多租户容器集群开放内核可编程能力之后，一个租户把网络程序挂到了别人的网卡上，还能通过固定映射表读到隔壁租户的连接跟踪表。平台组做过一次租户隔离演练，发现只要固定路径可猜，映射表就能被隔壁挂载；运维还发现卸载失败后固定路径一直残留，下一次加载直接命中旧程序。准入器只按程序类型拦，套接字过滤放行后网络程序也混进来；辅助函数允许列表没按程序类型区分；固定映射表跨租户共享；带可睡眠标志的程序被普通加载路径接受；尾调用能跳到别的租户的程序；挂载点控制组路径可以超出租户命名空间；许可证字段随便填；非特权加载标志没清掉；映射表容量和申请值不一致也通过；同名程序并发加载互相覆盖固定路径；卸载时映射表还被别的程序引用就释放；程序加载成功但挂载失败，固定路径留在原地成了孤儿。集群里几十个租户共用一套节点，不能因为一个租户的加载失败影响别人，平台组要求所有跨租户引用在加载前就拒绝。辅助函数不在该程序类型的允许列表里必须以 EPERM 失败，验证器日志要带 BPF_HELPER_DENIED；固定映射表路径跨出租户命名空间必须报 BPF_MAP_TENANT_MISMATCH；尾调用目标里混入其他租户的程序时调用必须失败且不能执行；同一固定路径并发加载只能成功一个，另一个返回 EEXIST 且不能覆盖。审计要求每次加载都记录租户、程序类型和固定路径。

## 运行方式
```bash
python -m pytest tests -q
```
