# GSB Bugfix Task
## 题面
手机银行接入客户端发起的后端认证做免密登录，上线后出现同一笔认证既走轮询又走回调，客户被扣了两次登录次数，还有人收到了别人的确认。客服只能看到客户被扣了次数，看不到是哪一步重复签发；风控要求把轮询、回调、确认三条路径的请求号都串起来。状态机允许认证请求号复用到不同的绑定消息；轮询间隔太短不返回减速错误；回调和轮询同时到达各自签发一个令牌；认证请求号跟发起它的客户端没有绑定关系；有效期限根本不看；提示令牌过期仍可用；用户还没确认就下发令牌；并发确认产生两条授权记录；回调入口不校验来源；请求被拒绝后仍能通过轮询成功；服务重启后待处理请求丢失，已批准的又重复投递；状态机允许拒绝状态直接跳到批准状态，中间没有终态保护。渠道侧说他们只按文档轮询，回调是后来加的能力，两边时序根本没对齐；这个问题在测试环境复现不了，只有生产并发上来才出现。同一认证请求号的轮询和回调并发只能签发一个令牌，第二个请求只能返回 invalid_grant；轮询间隔不足必须返回 slow_down 并拉长间隔；认证请求号只能由原客户端兑换，其他客户端报 unauthorized_client；重启后已批准未投递的请求只能补投一次，不能重复发令牌。渠道每天几十万笔，出了问题就是资金风险。

## 运行方式
```bash
python -m pytest tests -q
```
