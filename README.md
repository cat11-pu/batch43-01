# GSB Bugfix Task
## 题面
分支门店的防火墙做 IKEv2 响应端，最近换了长证书链，超过一半的店在高峰期连不上总部。抓包看发起方把 IKE_AUTH 拆成几片，响应端只收第一片就开始解析，后面几片当成新报文丢了；重传的发起方 SPI 与原来一致，响应端却又分配一套 IKE SA，隧道数越滚越多；NAT 探测到了，保活却还往五百端口发，穿越设备直接把包丢了；对端发 MOBIKE 地址更新，响应端不校验消息就直接改对端地址；消息窗口只记最高编号，乱序到达的分片被误判重放；加密通知载荷里的 Cookie 挑战被忽略，握手来回打转；协商里带的 DH 组不在支持列表也接受，重钥时才失败；子 SA 重钥时新旧两套同时可解密，防重放窗口却共用；分片证书回包不带分片标志，对端重组失败；IKE SA 删除没有级联到子 SA，残留隧道继续占资源；同一 NAT 出口后多个对端只按源地址查 SA，互相串隧道。门店白天要营业，不能重启防火墙，只能在线把状态机修顺。IKE_AUTH 分片必须收齐再验签，片不齐时回 IKE_FRAGMENT_INCOMPLETE；同一对 SPI 的重传只能命中已有 SA，不能新建；MOBIKE 地址更新必须来自已认证报文，否则报 IKE_MOBIKE_UNAUTH 并保持原地址；子 SA 重钥要原子切换，旧 SA 排空后才能删，期间不能用两把密钥解同一包。区域经理已经在催恢复时间。

## 运行方式
```bash
python -m pytest tests -q
```
