# GSB Bugfix Task
## 题面
等保测评前做自查，审计日志里少了整整一段登录失败记录，运维在系统里只看到一条积压溢出的计数。内核审计队列满了以后新事件被直接丢掉，连告警都没有；限流把认证失败事件压掉，攻击尝试全看不见；规则里先写永不匹配再写始终记录，后面的规则永远不生效；监视的目录被改名后，旧节点上的监视还在但路径对不上；排除规则写得太宽，把整个用户目录都排除了；重新加载规则时新旧两套叠加，同一事件记两遍；多段事件的后半段丢失，只剩前半段；定时任务的登录标识没有设置，事后无法归因；系统调用架构不匹配，32 位兼容调用漏记；并发更新规则只应用了一半；磁盘写满后审计直接停摆；容器命名空间里的事件完全没进主日志。这台机器是核心数据库宿主机，登录失败日志是调查的起点；审计规则有四百多条，谁也不敢乱删，运维试过调大缓冲区，结果内存先扛不住；安全队要求先保住认证类事件。等保测评就查这一项，日志缺口补不上就要重测。队列溢出必须记 AUDIT_BACKLOG_OVERFLOW 并对安全事件失败关闭，不能静默丢弃；规则重载必须原子切换，任何时刻只能看到旧规则或新规则；重复插入同一条规则要幂等，不能产生两份；日志轮转必须先落盘再删旧文件，不能丢未读事件。测评机构下周进场，别再出岔子。

## 运行方式
```bash
python -m pytest tests -q
```
