# GSB Bugfix Task
## 题面
运营商信令网割接后，两套流控制传输防火墙对多宿主关联的处理不一致，主路径断了切不过去，切换过去又冒出重复关联。局方验收时会拿仪表模拟主备路径交替断开，要求切换过程中一条信令都不能丢；值班还发现同一对端在两套防火墙上显示的主路径不一样。防火墙收到验证标签不对的初始化块也建关联；重复的凭据确认每次都新建一套关联；未验证地址发来的心跳能改主路径；没有认证块的动态地址配置也能加路径；流序列号回绕后重复投递；同一地址的不同端口被当成两条路径；进程崩溃重启后发送序号丢失，确认块能确认从未发过的序号；一个包里坏块导致整包丢弃，合法数据跟着丢；填充字节没跳过，块解析错位；校验和错误的包进入关联；多宿主地址列表更新不是原子替换，中间有半套地址；路径切换和重传计时器同时改状态，切换后重传还发到旧地址。信令面一断就是大面积投诉，局方要求先把关联状态管住，不能靠重启设备糊弄过去。初始化块验证标签错误必须回中止块并报 SCTP_BAD_VTAG，不能分配关联；同一四元组重复凭据确认只能命中已有发生关联，不能建第二条；无认证的动态地址配置必须拒绝并保持路径表不变；重启后要恢复各路径发送序号，收到确认未发送序号的确认块必须报 SCTP_SACK_INVALID。割接窗口只有半小时，回退也倒不回状态。

## 运行方式
```bash
python -m pytest tests -q
```
