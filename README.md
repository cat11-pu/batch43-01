# GSB Bugfix Task
## 题面
地市核心网割接后，UPF 旁边新上的隧道防护进程没能挡住探测流量，抓包能看到一堆不属于任何用户会话的报文被转进了内网。安全队怀疑有人拿隧道号扫地址，值班只能一条条比对控制面下发的表。现在的实现只查本地哈希，不跟会话表核对，未知隧道号照样放行；同一个隧道号被两个基站同时使用时，后到的表项把先到的覆盖，回程报文送错基站，用户突然断网；防重放窗口只放在内存，进程一重启就清零，隔夜的旧包又能上行；扩展头长度没有逐层读取，链式解析错位，后面的流标签取到了别的容器的值；没协商过的源地址发来的报文也收；不带会话的报文只要带流标签容器就通过；计费标识在网关重启后被复用，同一会话扣了两次费；分片报文只检查第一片，后续片绕过隧道校验直接转发；版本号被当成扩展标志解析；下行目的地址和隧道绑定不一致也放行；任意源发的回显请求都回，能被拿去做放大；两个转发线程同时更新隧道计数，面板上的流量一直偏小。割接窗口只有半小时，回退也倒不回状态，只能把校验做在转发路径上。未知隧道号必须按 GTP_UNKNOWN_TEID 丢弃并计数，不能回 ICMP；同一上行序号在窗口内只收一次，重复包静默丢掉且不推进窗口；重启后会话表和防重放窗口要从检查点恢复，重启前的包不能再转发；下行地址与隧道不匹配时报 GTP_UE_IP_MISMATCH。那套回归用例现在跑一遍，几乎全军覆没。

## 运行方式
```bash
python -m pytest tests -q
```
