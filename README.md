# GSB Bugfix Task
## 题面
开放平台给合作方做双向证书认证，最近一家合作方换了证书，结果一半请求被拒，另一半却把请求记到了别的租户头上。映射只取证书主题里的通用名，没看主体备用名；备用名里的通配符匹配过宽，一个证书能覆盖多个租户；证书过期后还有一段宽限期，过期证书照样能用；吊销列表几小时才刷新一次；中间证书链没有完整构建就判定有效；同一张证书被映射到两个租户，后配置的覆盖前面的；吊销查询超时按通过处理；证书序列号重复使用没有告警；网关注入的客户端标识头被上游直接信任；会话恢复时跳过了证书校验，恢复后的连接沿用了旧身份；并发请求对同一证书给出不同映射；在线证书状态查询超时也放行。开放平台上有四十多家合作方，证书由各家自己签发，网关每天处理几百万次调用；对方的技术团队只肯邮件沟通，安全队要求吊销检查不能软失败，运维已经把旧证书全部导出比对。对方已经暂停联调，要求今晚给结论。主体备用名不匹配必须报 MTLS_IDENTITY_MISMATCH；已吊销序列号必须拒绝，状态查询超时也要失败关闭并报 MTLS_REVOKED；一张证书只能映射一个租户，冲突时报 MTLS_MAPPING_CONFLICT；会话恢复必须保留原证书身份，不能重新映射。平台负责人要求今晚给合作方一个明确回复。

## 运行方式
```bash
python -m pytest tests -q
```
