# GSB Bugfix Task
## 题面
合规扫描说一批服务器的启动链不可信，查下来完整性度量的日志缺了关键几段，评估模式也没真正拦住被改过的程序。内存映射方式加载的可执行文件没有进度量列表；文件先被打开写入再执行，打开到执行的窗口没有校验；新挂载的磁盘没有套用度量策略；扩展属性的签名没有验证就当成可信；度量日志环形缓冲溢出后旧记录被静默覆盖；扩展平台配置寄存器的顺序和日志顺序对不上；评估失败时回退到允许执行；哈希算法和策略里写的不一致也接受；度量记录必须覆盖文件的创建、写入、执行和删除；命名空间里的挂载绕过了策略；并发写入时度量到半截内容；策略热加载不是原子替换；启动聚合值没有和日志对上。这批服务器跑的是核心交易，任何一次误拦都会影响开盘；合规方要求度量日志能和启动固件对上，运维手里只有一份两年前的策略模板，评估模式一直没敢开成强制。重启窗口每周只有一次。先把度量链补完整，别再让坏程序跑起来。评估失败必须拒绝执行并记 IMA_APPRAISAL_FAILED；打开写入后又执行同一文件必须按 IMA_TOMTOU_DENIED 拒绝；度量日志只能追加，重启后要能接上且不能覆盖旧记录；策略更新必须整批原子生效，不能出现半套规则。审计整改只剩三天，不能再返工。

## 运行方式
```bash
python -m pytest tests -q
```
