# GSB Bugfix Task
## 题面
限量商人改成按时间补货以后，蹲点抢购的投诉翻了几倍。两个玩家同时买最后一件，两边都提示购买成功，库存变成负一；补货直接把数量加满，不管上一轮还剩多少，实际库存超过上限；玩家重登之后，账号限购次数清零，同一件东西能反复买；补货定时器按开服那一刻起算，重启一次就整体往后推，越推越晚；商人刷新的瞬间被脚本传送走，库存和刷新状态一起丢了；背包满的时候购买扣了金币，物品掉在地上，被路过的人捡走；跨服玩家看到的库存不一样，A 服显示有货，B 服买了却失败；买了之后立刻掉线，库存减了，物品没进背包也没进邮件；补货和购买并发，补货把刚卖掉的又加回来；商人表里删掉的商品，旧库存还能继续买；补货时间显示成本地时间，跨时区玩家以为提前开了；同一账号在两个角色上分别计数，限购形同虚设。vendor_restock_clock.py 的 VendorRestockClock 要用条件更新管库存：购买时只有剩余数量足够才扣减，扣减、扣钱和发货在同一个事务里；补货按下一次补货时刻原子地把数量重置到上限，不能叠加；账号限购按账号而不是角色累计并落盘；补货时刻存绝对时间，重启后继续用原来的时刻；商人刷新和购买共用一把锁；删表的商品要同时下架剩余库存；跨服库存以中心记录为准。两条硬门禁：库存任何时刻不能为负，也不能超过配置上限；重启前后下一次补货时间不能漂移。tests/test_vendor_restock_clock.py 的十五条检查目前全是失败。

## 运行方式
```bash
python -m pytest tests -q
```
