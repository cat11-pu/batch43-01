# GSB Bugfix Task
## 题面
网管平台升级 SNMPv3 采集后，核心交换机的流量图每隔几小时就断一段，值班在设备上看到大量时间窗口错误。设备的引擎启动次数和时间没有落盘，重启后从零开始，平台拿旧值算认证直接失败；引擎标识每次重启都重新生成，平台缓存全废；认证协议配的是 SHA-256，设备却按 SHA-1 校验也放行；隐私密钥和认证密钥复用了同一份材料；发现报文能无限创建引擎缓存项，内存一直涨；未认证的报告报文也被当成有效响应；时间窗口放宽到十分钟，重放包照样能过；重复的请求编号被当成新请求，计数器翻倍；v3 告警里的引擎标识可以被伪造，平台照单全收；并发发现同一引擎时缓存互相覆盖；未知用户和密码错误返回不同错误码，能被拿来枚举账号；上下文名称不匹配也返回数据。这套采集覆盖三百多台设备，断档期间容量规划全失真，值班只能手工补数，补完还对不上。监控平台已经丢了半天的采集数据，先恢复。时间窗口外的请求必须回 usmStatsNotInTimeWindows 且不带任何数据；同一请求编号在窗口内只能处理一次，重复请求返回同一响应；引擎缓存要以引擎标识和用户为键，重启后恢复启动次数与时间；未知用户和认证失败必须返回同样的错误，不能泄露账号是否存在。值班还要求采集恢复后能补上断档的计数器。

## 运行方式
```bash
python -m pytest tests -q
```
