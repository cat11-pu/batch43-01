# GSB Bugfix Task
## 题面
数据中心两周内出了三次地址冲突，排查发现接入层的地址解析和 IPv6 邻居防护形同虚设，攻击者发几个通告就能把网关地址顶掉。值班只能翻交换机日志猜是哪台机器在冒充，定位一次要半天。防护进程一收到免费地址解析就改静态绑定；应答洪泛能把绑定表刷穿，正常表项被挤掉；IPv6 邻居通告只要带覆盖标志就盖掉静态项；非路由器主机发带路由器标志的通告也接受，流量直接被引走；地址冲突只记一条日志，不隔离端口；绑定表只用地址做键，不同虚拟局域网的同名地址互相覆盖；源地址未指定的请求也进入邻居状态机；对子网外地址做代理应答；老化线程和报文线程竞争，表项在使用中被删掉；动态地址分配 snooping 的绑定表没有参与校验；同一物理地址在两个端口之间来回跳，不触发任何保护；端口隔离解除后旧表项没有清掉，再次冲突时直接放行。接入交换机三百多台，型号跨三个厂商，改配置要走变更，软件侧得先把能拦的拦住。静态绑定不能被免费地址解析覆盖，违反时报 ARP_BINDING_LOCKED 并计数；同一地址在一秒内出现两个物理地址只能触发一次端口隔离，并发上报不能产生两次动作；重启后绑定表和隔离状态要从磁盘恢复，已隔离端口在显式解除前保持阻断；允许列表里的非路由器主机发路由器标志通告，必须丢弃并记 NDP_ROUTER_FLAG_DENIED。安全队给的时间只有一周，期间不能影响办公网。

## 运行方式
```bash
python -m pytest tests -q
```
