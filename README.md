# GSB Bugfix Task
## 题面
固话用户最近集中投诉打不通，IMS 侧看到大量重复注册，同一部话机在绑定表里占了好几条。注册服务器把挑战随机数重复使用，隔十分钟的旧请求也能通过；对端带过期标记时没有重新挑战，旧绑定继续生效；Contact 的 q 值被忽略，多个联系地址取最后一个；NAT 后的 received 和 rport 没有参与匹配，回包发到私网地址；expires 为零时没有删除对应绑定，只把整条记录清掉；认证头里没有 response 字段也接受；CSeq 相同的重放请求被当成新注册；收到 CANCEL 还回 200 OK；TCP 连接断了绑定不释放；同一 Call-ID 并发注册产生两条绑定；设备时间偏差大时随机数永远判过期。这套 IMS 承载全市固话，早高峰一乱就是几千个呼叫失败；厂商说注册状态机没问题，问题可能在我们侧，值班只能先把绑定表导出来比对。后台至少要能按应用拆出连接数，否则没法定位是谁占着地址池。投诉已经转到省公司，值班压力很大。重放的随机数必须回 401 并换新挑战，不能改动绑定；expires 为零只能删除匹配的 Contact，不能清掉整条记录；同一 Call-ID 和 Contact 并发注册只能保留一条绑定；过期挑战不能导致已有绑定被删除。值班要求先保证老用户能打进打出。

## 运行方式
```bash
python -m pytest tests -q
```
