# GSB Bugfix Task
## 题面
集团门户接 SAML 单点登录后，早上高峰总有一批人登录后被弹回，排查发现制品解析接口被重复调用。制品用过一次还能再换断言，同一个制品换出两个会话；制品没有绑定发起请求的服务提供方，换个实体也能兑换；中继状态直接拼到跳转地址，能被拿去做开放跳转；断言里的受众限制没检查，发给别的系统的断言也能用；响应里的请求关联标识缺失也接受；签名只盖了响应外层，断言本身没签；生效时间和过期时间没有留时钟偏差；断言编号重复使用没有拦截；实体标识大小写不一致就当成两个；制品解析走的是未加密回程通道；身份提供方主动发起的断言可以被重放；并发解析同一个制品产生两条会话。门户后面挂着三十多个业务系统，登录一抖，工单就堆起来；身份提供方是外部厂商，改配置要走对方窗口，值班只能先让用户重新登录，越重试越乱；安全队还要求把每次兑换的来源完整留痕。集团门户的登录开始随机失败。制品必须一次性使用，重复兑换报 SAML_ARTIFACT_REPLAY；受众不匹配必须报 SAML_AUDIENCE_INVALID 并拒绝登录；请求关联标识必须与未完成的请求对上，缺失时拒绝；断言编号缓存要跨重启保留，重放窗口内一律拒绝。先别让用户重复提交，越提交越乱。

## 运行方式
```bash
python -m pytest tests -q
```
