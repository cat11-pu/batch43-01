# GSB Bugfix Task
## 题面
播放器换成边下边播以后，用户拖动进度条的体验很差：拖到歌曲中间，开头先爆一声咔哒，然后才有声音；拖到结尾附近，播放器直接跳到下一首，最后两秒永远听不到；可变码率的文件时长算错，进度条走到头还有声音，或者没到头就停了；无缝专辑里上一首的尾巴和下一首的开头之间多出半秒静音；单曲循环的循环点落在编码器补的静音上，每圈都顿一下；拖动以后解码器没有重置，前几百毫秒是上一段的残留；从立体声切到单声道输出人声偏到一边，蓝牙耳机切回来采样格式没重新协商又直接静音；倍速播放时音调跟着变，语速快到听不清；暂停超过一分钟再继续，缓冲里的数据过期，声音断续；网络卡顿或者中途断网，恢复后要么同一块解码两遍、声音重复，要么从文件头重来、进度条倒退；同一首歌在不同手机上总时长差几百毫秒，歌词对不上；跳到文件开头，编码器延迟没有跳过，第一拍总是缺一点。这版播放器要同时覆盖安卓手机和车机，手里的文件从 mp3 到 flac 都有。任意位置拖动必须从关键帧或带预滚的位置开始解码，丢弃预滚样本，起点不能有爆音也不能缺拍；时长必须按容器和索引计算，可变码率文件不能只按文件大小估算；循环点必须落在解码后的样本边界上，编码器延迟和尾部填充要跳过；拖动与解码并发时旧请求必须作废，不能把上一段的数据混进新位置。

## 运行方式
```bash
python -m pytest tests -q
```
