# GSB Bugfix Task
## 题面
邮件网关的对外投递被安全扫描判了高危，说部分域名明明发布了强制传输策略，网关还是在明文链路上把信发了出去。对端管理员说他们只负责发策略，怎么执行不在他们的排障范围，出了问题全落到我们这边；邮件一旦明文出去就收不回来，只能事前拦住。翻日志发现中间设备把加密升级能力从问候响应里抹掉后，网关继续按明文投递；策略过了有效期还在用；策略里的邮件交换记录匹配规则没生效，任意记录都被放行；策略处于测试模式却按强制模式拒信，正常邮件被退；证书链有效但名字不匹配也接受；投递报告重复生成，有时根本不发；问候响应里的换行没过滤，能注入假能力；加密握手前流水线发来的命令照样执行；域名认证查询没检查安全扩展的验证位；四开头的临时失败被当成永久失败直接退信；多个邮件交换记录在加密失败后逐个降级到明文；同域并发投递各自拉一次策略，把对端策略服务打出风暴。网关后面是几百个业务域，退一封信就是一笔订单，运维还要求每次拒信能说清是策略问题还是连接问题。对端宣告加密能力后又抹掉时，必须以 STARTTLS_REQUIRED 失败并留在队列，禁止明文投递；强制策略且邮件交换记录不匹配时，要在收件人阶段返回 550 5.7.1；策略刷新必须整批原子替换，刷新期间连接只能看到旧策略或新策略，不能看到半套记录；证书关联记录不匹配只能判投递失败，不能回退明文。把回归集拉起来跑，失败项一眼望不到头。

## 运行方式
```bash
python -m pytest tests -q
```
