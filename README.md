# GSB Bugfix Task
## 题面
客户是做在线教育的，晚高峰两千人同时上课，视频会议上了 simulcast 以后，弱网体验反而更差，客户直接拿这段录屏来投诉。带宽掉下去切到低层，画面卡住等关键帧，黑屏两秒；切层的时候订阅端疯狂请求关键帧，编码器直接打满；切完音频和视频不同步，口型差半秒；带宽回升了却不切回高层，一直糊着；两个订阅者要不同层，发布端只发了一层，另一个看不到；重连以后层号错乱，收到不属于自己的层；关键帧请求没去重，同一帧被请求几十次；屏幕共享和摄像头共用层配置，共享出来的文字看不清；丢包时 NACK 和 PLI 一起触发，重复请求；切层以后 RTP 时间戳不连续，播放器直接报错；发布端重启订阅关系全丢，所有人黑屏；带宽估计把音频也算进去，视频层永远选低一档。simulcast_lane_select.py 的 SimulcastLaneSelect 管 select、request_keyframe、apply、restore。同一发布流同一时刻只能激活一个目标层，重复切层返回 same_layer 且不重复请求关键帧；切层必须在新层首个关键帧到达后原子切换，切换前继续显示旧层，不能黑屏；关键帧请求按帧号去重，一秒内同一目标最多一次；发布端重启后订阅关系从持久化恢复，恢复前不能推错层。test_simulcast_lane_select.py 的十五条用例，会议组拿弱网模拟器跑了一轮，全部失败。

## 运行方式
```bash
python -m pytest tests -q
```
