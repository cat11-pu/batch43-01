# GSB Bugfix Task
## 题面
手机用户升级到纯 IPv6 接入后，一半应用连不上，后台看 NAT64 的地址池两个小时就耗尽了。会话老化只看 TCP，UDP 和 ICMP 的映射一直挂着；464XLAT 要求端口奇偶保持，转换后映射到的端口奇偶反了；内网访问内网的 hairpin 流量没有做二次转换，回包直接丢；分片报文先转换再重组，片偏移被改坏；ICMP 错误包里的内层五元组没有反查，错误送不到源端；TCP 状态跟踪不认复位包，连接关掉映射还在；会话键只算源地址不算源端口，同地址不同应用串会话；网关重启后映射全丢，回程流量找不到入口；同时打开的两个连接给同一内网端口分配了两次；DNS64 合成的地址没标作用域，跨域被误用；TCP、UDP、ICMP 用同一个老化时间；并发申请端口时两个线程都以为抢到了。先查映射表，别急着扩容地址池。同一五元组并发建流只能产生一个映射，第二个请求复用同一个；重启后要恢复映射和剩余生存时间，回程包不能丢；ICMP 错误必须能反查到现有会话，否则按 NAT64_NO_SESSION 丢弃；464XLAT 流必须保持端口奇偶，违反时报 NAT64_PORT_PARITY。客服说投诉量还在涨。

## 运行方式
```bash
python -m pytest tests -q
```
