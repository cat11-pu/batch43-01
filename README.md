# GSB Bugfix Task
## 题面
两个机房做 MACsec 互联后，链路每隔几分钟就闪断，交换机日志里能看到同一个安全通道装了两把不同的密钥。密钥协商还没选出密钥服务器就先把 SAK 装了进去；防重放窗口按安全通道算而不是按安全关联算，换密钥后旧计数干扰新计数；参与者列表从不清理，掉线交换机一直留在里面；控制帧的完整性校验被跳过，伪造的协商帧也能过；加密套件不匹配时没有拒绝，直接降级；密钥服务器优先级相同时没有决出唯一一个；不同连接关联复用了同一把 SAK；包序号用尽后不重钥，链路直接停；EAPOL 协商帧能被重放；重启后连接关联密钥丢了，SAK 却还在用；两个选举线程同时宣布自己是服务器；机密性偏移算错，部分字节没加密。这两个机房承载交易系统的双活链路，闪断一次就要人工切流；交换机厂商和光模块厂商互相推，运维夹在中间，安全队又说不能先降级再排查。值班只能在凌晨做实验。链路加密一断，两个机房的互联就全裸奔了。完整性校验失败必须丢弃并记 MKA_ICV_INVALID；SAK 只能在选举完成后原子安装，不能出现两把同时生效；包序号用尽必须强制重钥并拒绝旧 SAK；重启后连接关联密钥和 SAK 要一起恢复，恢复不了就失败关闭。安全队要求先停掉自动降级。

## 运行方式
```bash
python -m pytest tests -q
```
